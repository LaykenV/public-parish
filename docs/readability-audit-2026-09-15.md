# Local issue readability audit

Reviewed September 15, 2026 against released commit `f46a933` and current public
issue queries. The owner shared reader feedback about formal titles and repeated
explanations under "Why this may matter." This audit inspects five published
issues. Pafford EMS is the likely match; the reader's exact URL is unconfirmed.

## Findings

The existing layout provides an introduction, evidence controls and a timeline.
The live EMS page repeats almost the same contract description under two
importance factors. Its introduction lists records without explaining which
update the reader is looking at. Several other issues preserve government
phrasing where their accepted citations already support simpler wording.

| Issue | Main problem | What the accepted evidence allows |
| --- | --- | --- |
| Pafford EMS | Contract background and monthly report receipt blur together; two factors repeat the contract scope | Explain the dated report action first, then the contract background |
| Constantin/Dijon | A project number replaces the recognizable project name | Name the project and explain the two different services and spending caps |
| Library tax | The title leads with "ad valorem"; the summary leads with election procedure | Say property tax and explain the documented library uses |
| Holiday Village brush truck | Purchase authorization repeats under both summary and assets | Keep the authorization brief and put its spending cap in the money explanation |
| Lena-Flatwoods | Summary and both factors repeat the bid authorization | Explain the bid stage once, then the estimate and funding source |

These observations do not establish audience-wide usability. The five cases are
a targeted editorial sample, not a random sample or a measured comprehension test.

## Proposed copy and evidence

These are manually prepared review drafts, not model outputs or new accepted
publications. Each section names the current public page and the accepted
citation references for the suggested wording. Independent review and a new
accepted version must precede any replacement in the app. The report retains
current uncertainty; it does not establish what happened after the saved records.

## Local prompt changes

Extraction now asks for a recognizable headline, familiar wording and a short
brief about the specific action. Issue drafting separates a report update from
contract history and asks each consequence explanation to add supported detail.
The independent issue reviewer explicitly permits faithful plain-language
paraphrases and still rejects unsupported effects or a changed procedural stage.

Prompt versions are extraction `v1.17`, issue drafting `v1.7` and issue review
`v1.2`. The existing run keys include those versions. No schema, score rubric,
publication policy, accepted version or UI layout changed. A prompt update does
not rewrite existing publications and is not evidence of better model output.

## Verification and limits

- Read the production issue list and five issue details through anonymous public
  queries. Compared their titles, summaries, factors, linked decisions and exact
  accepted excerpts. No owner data or resident records were queried.
- Opened the live EMS page in Chromium at desktop and phone widths and inspected
  both screenshots. The duplication appears in the rendered page.
- Reopened the two Baton Rouge agendas and checked the named items. The Rapides
  PDF host rejected direct retrieval with HTTP 403, so those comparisons rely on
  the app's accepted citation excerpts. The full EMS report was not inspected.
- Local validation results are recorded in [the work queue](work.md). Automated
  checks validate integration, not the quality of newly generated prose.
- No paid generation, fresh evidence ingestion, backend sync, publication,
  notification, commit, push or deployment occurred.

The next bounded evaluation should reuse these five input sets in development,
compare generated drafts with these examples, and check every proposed claim
against its citations. Any absent service effect stays absent. A human review
should ask whether the reader can name the action, explain its supported effect,
and distinguish approval from completion without opening the PDF.
